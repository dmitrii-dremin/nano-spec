# NanoSpec

Ultra lightweight SDD framework. Минимум документации, достаточный для правильной реализации, проверки и продолжения работы другим агентом.

Текущая версия: **0.1.0**. Это первая экспериментальная версия философии и скиллов; её эффективность ещё предстоит проверить на реальных задачах.

## Начать

Прочитай [философию](PHILOSOPHY.md). Для работы выбери нужный скилл:

| Скилл | Когда нужен | Результат |
| --- | --- | --- |
| [nanospec-shape](skills/nanospec-shape/SKILL.md) | Уточнить и подготовить задачу | Достаточная постановка или конкретный нерешённый вопрос |
| [nanospec-apply](skills/nanospec-apply/SKILL.md) | Выполнить или продолжить разрешённую задачу | Реализация, проверка и необходимые обновления записей |
| [nanospec-check](skills/nanospec-check/SKILL.md) | Отдельно оценить готовность постановки или соответствие реализации | Существенные пробелы либо подтверждённый результат с границами проверки |

Это независимые действия. Не требуется вызывать все три: `apply` включает проверку своей работы, а `check` полезен для отдельного ревью.

Скиллы в `skills/` — исходники пакета, каждый самодостаточен. Для первого прогона достаточно дать агенту путь:

```text
Прочитай C:/Programming/nano-spec/skills/nanospec-shape/SKILL.md
и используй его для подготовки следующей задачи: ...
Рабочий репозиторий: ...
```

Для выполнения укажи `nanospec-apply/SKILL.md`, постановку и целевой репозиторий. Пути выше относятся к этой локальной копии; в другом окружении подставь путь к NanoSpec.

Для автоматического обнаружения установи нужные папки скиллов в каталог скиллов своего агента. Размещение исходников в этом репозитории само по себе не устанавливает их в другие проекты. CLI и зависимости для применения версии 0.1.0 не нужны.

Следующий этап — [практические прогоны](TESTING.md).

## Версии и совместимость

Версионирование следует [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). `VERSION` задаёт версию всего пакета: философия и скиллы выпускаются вместе.

Публичный контракт NanoSpec — имена скиллов, их назначение и границы действий, смысл постановки и завершения работы, правила выбора контекста и хранения знаний из философии. Формулировки Markdown и названия необязательных разделов не являются машинным API. У NanoSpec 0.1.0 нет парсера записей.

Ветка `0.y.z` экспериментальная. Наше соглашение до 1.0.0:

- `PATCH`: исправления и уточнения без изменения контракта.
- `MINOR`: новые возможности или изменение контракта; несовместимость и способ перехода указываются в changelog.
- `1.0.0`: фиксация стабильного контракта. После неё несовместимые изменения увеличивают `MAJOR`, совместимые возможности — `MINOR`, совместимые исправления — `PATCH`.

Содержимое уже выпущенной версии не изменяется: исправление получает новую версию. При увеличении старшего компонента младшие сбрасываются в ноль. Версия пакета не требует отдельного номера в каждой рабочей записи проекта.
